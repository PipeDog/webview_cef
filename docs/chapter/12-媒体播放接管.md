# 媒体播放接管（Media Player Takeover）

## 背景与目标

从 https://cef-builds.spotifycdn.com 下载的 CEF 内核（Spotify 构建版）因版权问题**不支持 MP3、MP4（H.264/AAC）等专利编码格式**的播放：`<video>` / `<audio>` 页面元素无法播放这些常见格式。

整体目标：**在不更换 CEF 内核版本的前提下**，让 Web 页面中的 MP3/MP4 等媒体资源可以被播放。

解决思路：通过 **JS 注入层劫持页面媒体元素**，在用户触发播放时接管播放行为，改用 **Flutter 原生播放器 fvp（基于 libmdk）** 在 Web 容器之上渲染播放 UI，并通过 **JS Bridge** 与页面保持状态同步（页面代码几乎无感知：`paused` / `currentTime` / `duration` / `ended` 等属性与事件全部由原生侧回灌）。

设计文档：根目录 `media_player_design.md`（协议与决策）、`media_player_implementation.md`（实现说明）。

## 总体架构

```
┌───────────────────────────── Web 页面 ─────────────────────────────┐
│  <video> / <audio> 元素（属性/事件被 shim，属性由原生侧回灌）         │
│   HTMLMediaElement.prototype.play/pause 被劫持                      │
└─────────────────────────────┬──────────────────────────────────────┘
                              │ $cef.MediaPlayer.postMessage（V8 扩展通道，frameId 随消息附加）
┌─────────────────────────────▼──────────────────────────────────────┐
│ media_player_js_bridge.dart   JS 消息编解码 + Dart→JS 写回脚本生成   │
└─────────────────────────────┬──────────────────────────────────────┘
┌─────────────────────────────▼──────────────────────────────────────┐
│ MediaPlayerController（ChangeNotifier，每 WebViewController 一个）    │
│   · 状态机：Idle → Loading → Playing ⇄ Paused → Ended / Error       │
│   · fvp (mdk.Player) 驱动：解码、播放、seek、音量和倍速              │
│   · 250ms 轮询 position → 通知 UI + 写回页面                        │
└───────────────┬──────────────────────────────────┬─────────────────┘
                │ notifyListeners                  │ executeJavaScriptInFrame
┌───────────────▼──────────────────┐   ┌───────────▼─────────────────┐
│ MediaPlayerOverlay（UI 层）        │   │ C++ 侧（webview_handler.cc） │
│  全屏 / 浮窗 / 音频 mini bar       │   │ 按 frameId 在所属帧执行 JS    │
└──────────────────────────────────┘   └─────────────────────────────┘
```

- **JS 注入层**（`media_player_js_injection.dart`，字符串常量）：由渲染进程在**每帧 V8 上下文创建时、任何页面脚本运行之前**执行，劫持 `HTMLMediaElement.prototype.play/pause`；负责 gesture 检测、媒体 URL 解析、元素移除监控、Dart→JS 写回分发（`window.__cefMediaPlayerDispatch`）。
- **JS Bridge**（`media_player_js_bridge.dart`）：解码 `$cef.MediaPlayer` 通道传入的 JSON 消息为强类型请求对象；生成写回页面的 JS 片段（JSON 直接嵌入为 JS 对象字面量，无需转义）。
- **控制器**（`media_player_controller.dart`）：驱动状态机与 fvp 播放器，是 UI 与页面之间的状态中枢。
- **UI 层**（`media_player_overlay.dart`）：三种形态（见下文），放在 WebView 的 Stack 顶层。
- **C++ 侧**：`mediaPlayerInjectScript` 经 extra_info 随浏览器创建传入渲染进程；`OnContextCreated` 提前注入；`executeJavaScriptInFrame` 按 frameId 定位帧执行写回脚本。

## 核心流程

### 1. 用户点击播放

页面 JS 调用 `video.play()` → 被劫持的 `HTMLMediaElement.prototype.play`：

1. **gesture 检测**：`navigator.userActivation.hasBeenActive`（兜底：500ms 交互窗口）。无手势 → 拒绝 Promise（`NotAllowedError`，模拟浏览器自动播放策略）。
2. 有手势 → 解析媒体 URL（`currentSrc` / `src` / `<source>`，相对地址基于本帧 location 解析为绝对地址）→ `entry.state = 'loading'` → 发送 `mediaPlayRequest`。
3. 返回一个**永不 resolve 的 Promise**：播放期间保持 pending；玩家关闭时以 `AbortError` 拒绝（页面 `await play()` 不悬挂）；fvp 加载失败时以 `NotSupportedError` 拒绝。

### 2. 原生接管播放

`MediaPlayerController.onPlayRequest`：

- 同一元素重播（页面自定义控件）：paused/ended → 恢复；error → 重试。
- 新元素：**互斥**——先拆除上一个播放，再加载新元素。

`_loadMedia` 流程：`player.media = url` → `prepare()` → 读取 `mediaInfo`（时长、视频流宽高）→ `updateTexture()` 创建纹理 → `player.state = playing` → 写回 `mediaPlayResult(success)` → 启动 250ms 轮询。

### 3. 状态同步（写回）

轮询与状态变化时，通过 `executeJavaScriptInFrame` 执行 `window.__cefMediaPlayerDispatch("state", {...})`：

- B 级字段：`paused` / `currentTime` / `duration` / `ended`
- Phase 3 扩展：`volume` / `muted` / `playbackRate` / `readyState` / `networkState` / `buffered` / `seeking` / `waiting`

页面侧 shim 同步更新元素属性，并按 `>=250ms` 节流派发 `timeupdate`，按状态迁移派发 `play` / `pause` / `ended` / `seeking` / `seeked` / `waiting` / `canplay` / `loadedmetadata` 等事件。

### 4. 页面属性/操作反向同步

页面侧对元素属性的写入转发给原生播放器：

- `el.paused = true`（调用 `pause()`）→ `mediaPauseRequest`
- `el.currentTime = x`（页面自定义进度条）→ `mediaSeekRequest`
- `el.volume` / `el.muted` / `el.playbackRate` 赋值 → `mediaPropertyChange`

## 状态机与轮询

```
Idle → Loading → Playing ⇄ Paused → Ended / Error
  ↑                                     │
  └────────── 重播 / 重试 ───────────────┘
```

- **轮询**：250ms 定时读取 `player.position`，更新 `_position` 并通知 UI、写回页面。
- **ended 兜底**：部分短视频（如 1.9s）fvp 不派发 `MediaStatus.end`，状态会卡在 playing。轮询检测 `position >= duration - 150ms` 视为结束，并把 `position` 对齐到 `duration`（进度条定格 100%）。
- **错误延迟确认**：fvp 的 `onEvent` 错误事件多为**非致命**（丢帧、音频抖动），直接报错会导致"实际播放正常却提示无法播放"。实现上错误事件仅记录 `_pendingError`，轮询确认播放停滞（连续 3 次无 position 变化，约 750ms）才真正进入 Error 态；`MediaStatus.invalid` 仍立即报错。
- 音频播放结束自动收起 mini bar（close 并复位元素）；视频播放结束保留 UI（重播按钮）。

## 消息协议

### JS → Dart（`$cef.MediaPlayer.postMessage`，frameId 由 C++ 侧附加）

| cmd | 载荷 | 触发时机 |
|-----|------|----------|
| `mediaPlayRequest` | mediaId, url, type, title, gesture | 用户手势驱动的 play() |
| `mediaPauseRequest` | mediaId | 页面调用 pause() |
| `mediaSeekRequest` | mediaId, position(秒) | 页面 currentTime 赋值 |
| `mediaPropertyChange` | mediaId, property, value | 页面 volume/muted/playbackRate 赋值 |
| `mediaElementRemoved` | mediaId | 元素被移出 DOM 或 display:none |

### Dart → JS（executeJavaScriptInFrame 执行）

| 消息 | 载荷 | 语义 |
|------|------|------|
| `mediaStateUpdate` | 完整状态字段集 | 写回元素属性并派发事件 |
| `mediaPlayResult` | mediaId, success, error | play() 启动结果，失败时拒绝页面 Promise |
| `mediaClosed` | mediaId | 播放器关闭，元素复位，挂起的 play() 以 AbortError 拒绝 |

## UI 形态

| 形态 | 适用 | 说明 |
|------|------|------|
| **全屏** | 视频默认 | 视频铺满 WebView 完整高度（控件叠加其上，不占布局空间）；顶栏（标题/浮窗切换/关闭）、底栏（进度/播放/音量/倍速）；点击视频区域切换控件显隐；ended 显示胶囊重播按钮 |
| **浮窗** | 视频（全屏切换） | 可拖动（四方向留 10px 边距），三档尺寸循环；Header 与细进度条叠加显示；点击视频区域切换显隐；ended 仅显示重播 icon；播放不停顿 |
| **音频 mini bar** | 音频默认 | 可拖动紧凑胶囊条（播放/进度/音量/倍速/关闭）；播放结束自动收起 |

通用要素：加载中指示器、统一错误面板（含 blob/MSE 专属文案）、重播按钮、`_AspectVideo` 等比缩放（读取媒体流原始像素宽高，窗口拉伸不变形）、进度条 250ms 补间平滑推进。

## C++ 侧改动（common/）

- **`webview_app.cc/h`**：`OnBrowserCreated` 从 extra_info 缓存 `mediaPlayerInjectScript`；`OnContextCreated` 在**页面脚本之前**对每帧 V8 上下文执行注入脚本（幂等，window flag 防重复）；注入失败输出诊断日志。
- **`webview_handler.cc/h`**：新增 `setMediaPlayerInjectScript()`；`createBrowser` 通过 extra_info 将脚本传给渲染进程（覆盖 OOPIF 子进程）；新增 `executeJavaScriptInFrame(browserId, frameId, code)`——按 CEF 122+ 字符串 frameId 用 `GetFrameByIdentifier` 定位帧执行脚本，帧已随导航失效则静默丢弃。
- **`webview_plugin.cc`**：缓存 method channel 传入的 `mediaPlayerInjectScript`。

## 关键设计决策（要点）

- **不换内核、不改 URL**：劫持元素而非解码器，页面代码与网络栈不动。
- **通道免注册**：`$cef.MediaPlayer` 与普通 JavaScriptChannel 走同一 V8 Proxy 机制，setJavaScriptChannels 是 no-op。
- **frameId 贯穿**：JS→Dart 消息原生附带所属帧 id；写回脚本执行在元素所属帧（跨域 iframe / OOPIF 也覆盖）。
- **互斥**：一个控制器同一时刻只服务一个媒体元素。
- **blob/MSE 不支持**：URL 为空或 `blob:` 前缀 → 专属文案"该视频格式不支持"。
- **元素移除即关闭**：MutationObserver 监控 DOM 移除与 display:none（含 getComputedStyle 节流兜底）。
- **导航即关闭**：跨文档导航时关闭播放器并复位元素。

## 已知限制

- blob/MSE（流式）媒体源暂不支持（见设计决策 11）
- 无手势的自动播放按浏览器策略拒绝
- 错误事件延迟确认最多 750ms（避免误报；真故障时错误面板延迟出现）
- fvp 依赖：`pubspec.yaml` 新增 `fvp`（libmdk 封装），各平台构建时需链接 libmdk 动态库
