# 接入指南

本文档面向插件使用者，介绍如何将 `webview_cef` 集成到你的 Flutter 桌面应用中。
涵盖环境准备、四平台配置、最小示例、常用功能、配置项和 FAQ。

> **关于其他文档**：本文档聚焦**使用方式**；内部原理请查阅对应章节——
> [架构概览](1-架构概览.md)、[Dart API 参考](2-Dart层API.md)、[JSBridge 详解](4-JSBridge详解.md)、[构建与集成](7-构建与集成.md)。

## 1. 环境要求

### 版本要求

| 项目 | 最低版本 |
|------|---------|
| Flutter | ≥ 3.27.0 |
| Dart | ≥ 3.6.0 |
| C++ 工具链 | C++20（CEF 149 要求，MSVC 2019+ / Clang 12+ / GCC 11+） |

### 各平台工具链

| 平台 | 系统版本 | 必装工具 | 安装命令 |
|------|---------|---------|---------|
| macOS | macOS 12.0+ | Xcode、CocoaPods、CMake、Ninja | `brew install cmake ninja` |
| Windows | Windows 10+ x64 | Visual Studio（MSVC）、CMake ≥ 3.14 | VS Installer 勾选"使用 C++ 的桌面开发" |
| Linux | 主流发行版 x64 / arm64 | Clang、CMake、Ninja、GTK+3 | `sudo apt install clang cmake ninja-build libgtk-3-dev pkg-config` |
| eLinux | 嵌入式 Linux（arm64 / x64） | flutter-elinux SDK | 目标设备需预装运行时库 |

> **网络要求**：首次构建需从 Spotify CDN 下载 CEF 标准发行版（约 330 MB）。可通过离线缓存加速，见[第 3 节](#3-添加依赖)。

### eLinux 运行时依赖

目标设备需预装以下库：

```bash
sudo apt install libnss3 libnspr4 libfontconfig1 libasound2
```

## 2. 添加依赖

### pubspec.yaml

```yaml
dependencies:
  webview_cef: ^0.5.1
```

或通过命令行添加：

```bash
flutter pub add webview_cef
```

也可使用 Git 依赖（开发版本）：

```yaml
dependencies:
  webview_cef:
    git:
      url: git@github.com:PipeDog/webview_cef.git
```

### CEF 下载

首次构建时，CEF 二进制（约 330 MB）会自动从 Spotify CDN 下载，各平台触发时机：

| 平台 | 下载触发 | 存放位置 |
|------|---------|---------|
| macOS | `pod install`（`flutter run` 自动触发） | `macos/third/cef/` |
| Windows / Linux / eLinux | CMake 构建时 | `third/cef/` |

下载的 CEF 包包含运行时二进制（dylib / dll / so）、资源文件（.pak、icudtl.dat）、头文件
和 `libcef_dll_wrapper` 源码（本地编译）。完整文件流转见[构建与集成](7-构建与集成.md)。

### 离线加速

如果网络环境访问 Spotify CDN 较慢，可预先将 CEF tarball 放入系统级缓存目录
`~/.cef/tar/`（Windows: `%USERPROFILE%\.cef\tar\`），构建时将自动跳过下载。

预下载脚本（在项目根目录执行）：

```bash
# macOS（arm64 + x86_64）
bash cef_tar/download_cef_tars.sh

# Windows
bash cef_tar/download_cef_tars.sh --platform windows

# Linux x64
bash cef_tar/download_cef_tars.sh --platform linux

# Linux arm64
bash cef_tar/download_cef_tars.sh --platform linux-arm64
```

也可通过环境变量 `CEF_TAR_CACHE_DIR` 自定义缓存路径。详见 `cef_tar/README.md`。

## 3. 平台配置

每个平台的 Flutter 项目需要少量手工配置才能正常运行 CEF。以下是各平台的必做步骤。

### 3.1 macOS

**1. 部署目标 ≥ 12.0**

修改 `macos/Podfile` 第一行（如不存在则添加）：

```ruby
platform :osx, '12.0'
```

同时在 Xcode 中打开 `macos/Runner.xcworkspace`，将 Runner target 的
**macOS Deployment Target** 设为 `12.0` 或更高。

**2. 嵌入 CEF Helper 子进程**

在 `macos/Podfile` 的 `post_install` 块末尾添加：

```ruby
post_install do |installer|
  installer.pods_project.targets.each do |target|
    flutter_additional_macos_build_settings(target)
  end
  # webview_cef: embed the CEF helper sub-process apps
  require File.expand_path(
    'Flutter/ephemeral/.symlinks/plugins/webview_cef/macos/embed_cef_helpers.rb', __dir__)
  WebviewCEF.install_helper_phase(installer)
end
```

> **注意**：不添加 helper 钩子也能编译运行，但 CEF 将回退为**单进程模式**——无沙箱隔离，
> 无崩溃保护，V8 proxy resolver 被禁用。生产环境务必添加此钩子。

**3. 编译 wrapper（Release 模式）**

使用 `flutter run --release` 或 `flutter build macos --release` 时，需设置环境变量使
`libcef_dll_wrapper` 以 Release 模式编译（与 CEF Release 二进制 ABI 匹配）：

```bash
export CEF_WRAPPER_BUILD_TYPE=Release
flutter build macos --release
```

**验证**：

```bash
cd example && flutter run -d macos
```

### 3.2 Windows

**修改 `windows/runner/main.cpp`**，加入两处代码：

**第一处**：文件头引入 + `wWinMain` 首行初始化 CEF 子进程：

```cpp
#include "webview_cef/webview_cef_plugin_c_api.h"

int APIENTRY wWinMain(_In_ HINSTANCE instance, _In_opt_ HINSTANCE prev,
                      _In_ wchar_t *command_line, _In_ int show_command) {
  // MUST be the first call in wWinMain
  int exit_code = initCEFProcesses(instance);
  if (exit_code >= 0) {
    return exit_code;
  }

  // ... 原有的 AttachConsole、CoInitializeEx、DartProject、窗口创建等代码 ...
```

> **说明**：`initCEFProcesses(instance)` 在处理子进程类型（GPU、Renderer、Plugin 等）时
> 返回该子进程的退出码；浏览器进程返回 `-1`（无特殊值时），正常继续执行 Flutter 主逻辑。

**第二处**：消息循环末尾加入键盘转发：

```cpp
  ::MSG msg;
  while (::GetMessage(&msg, nullptr, 0, 0)) {
    ::TranslateMessage(&msg);
    ::DispatchMessage(&msg);
    // Enable CEF keyboard input
    handleWndProcForCEF(msg.hwnd, msg.message, msg.wParam, msg.lParam);
  }
```

完整示例见 `example/windows/runner/main.cpp`。

**可选 CMake 选项**：

| 选项 | 默认值 | 说明 |
|------|--------|------|
| `WEBVIEW_CEF_GPU_TEXTURE` | `ON` | 启用 D3D11 共享纹理零拷贝渲染；关闭则回退软件像素缓冲 |
| `WEBVIEW_CEF_USE_DEBUG_CEF` | `OFF` | Debug 构建仍链接 CEF Release 二进制（避免 CEF Debug DCHECK 在 IME 输入时崩溃） |

**验证**：

```bash
flutter run -d windows
```

### 3.3 Linux

**无需手动修改 runner 代码**。CMake 构建时，`target_modifier/modify_target.sh`
会自动在 `linux/main.cc` 和 `linux/my_application.cc` 中加入 CEF 所需的初始化调用和键盘事件钩子。

只需确保工具链已安装：

```bash
sudo apt install clang cmake ninja-build libgtk-3-dev pkg-config
```

**可选**：安装 `xclip` 以支持粘贴功能：

```bash
sudo apt install xclip
```

> `xclip` 缺失不影响编译，但 CEF 区域的粘贴操作将不可用。

**验证**：

```bash
flutter run -d linux
```

### 3.4 eLinux

使用 **flutter-elinux SDK**（不是标准 Flutter CLI）构建：

```bash
flutter-elinux pub get
flutter-elinux build elinux --release
```

产物位于 `build/elinux/x64/release/bundle/`，运行时需指定后端：

```bash
./bundle/webview_cef_example -b .
```

**后端选择**：通过 `FLUTTER_TARGET_BACKEND_TYPE` 环境变量控制（`wayland` / `gbm` /
`eglstream` / `x11`，默认 `wayland`）。

**重要特性**：

| 特性 | 说明 |
|------|------|
| 图形后端 | Wayland / DRM-GBM（无 GTK / X11 依赖） |
| GPU 渲染 | 仅软件渲染，不支持 GPU 共享纹理 |
| 键盘输入 | `hasNativeKeySupport == false`，由 Dart 侧处理 |
| Sandbox | 默认 `--no-sandbox`（嵌入式文件系统通常不支持 SUID sandbox） |

**验证**：

```bash
flutter-elinux build elinux --release
./build/elinux/x64/release/bundle/webview_cef_example -b .
```

### 平台配置对照

| 平台 | 必须的手工步骤 | 自动处理 |
|------|--------------|---------|
| macOS | ① Podfile `platform :osx, '12.0'` ② `post_install` helper 钩子 | CEF 下载 + wrapper 编译 |
| Windows | ① `initCEFProcesses(instance)` ② `handleWndProcForCEF(...)` | CEF 下载 + wrapper 编译 |
| Linux | 无 | runner 自动打补丁 + CEF 下载 |
| eLinux | 无（原生侧） | flutter-elinux 构建；运行时库需手工安装 |

## 4. 第一个 WebView

以下是一个完整的最小可运行示例，展示了 `webview_cef` 的完整生命周期。
代码基于 `example/lib/main.dart` 精简而来。

```dart
import 'package:flutter/material.dart';
import 'package:webview_cef/webview_cef.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatefulWidget {
  const MyApp({super.key});

  @override
  State<MyApp> createState() => _MyAppState();
}

class _MyAppState extends State<MyApp> {
  WebViewController? _controller;
  bool _ready = false;

  @override
  void initState() {
    super.initState();

    // ① Initialize CEF engine — call once per app
    WebviewManager()
        .initialize(
          userAgent: "my-app/1.0",          // optional
          processMode: ProcessMode.processPerSite,
        )
        .then((_) async {

      // ② Create a webview controller
      _controller = WebviewManager().createWebView(
        loading: const Center(child: CircularProgressIndicator()),
      );

      // ③ Register event listener BEFORE controller.initialize()
      _controller!.setWebviewListener(WebViewEventsListener(
        onPageStarted: (controller, url) {
          debugPrint("Loading: $url");
        },
        onPageFinished: (controller, url) {
          debugPrint("Loaded: $url");
        },
        onPageFailed: (controller, url, error) {
          debugPrint("Failed: $url (${error.code} ${error.message})");
        },
        onNavigateRequest: (controller, url) {
          // Block navigation to spam.com
          if (url.contains('spam.com')) {
            controller.stopLoading();
            return NavigationPolicy.cancel;
          }
          return NavigationPolicy.allow;
        },
        onProgressUpdated: (controller, progress) {
          debugPrint("Progress: ${(progress * 100).toStringAsFixed(0)}%");
        },
        onRenderProcessTerminated:
            (controller, status, errorCode, errorString) {
          debugPrint("Renderer crashed, reloading...");
          controller.reload(); // CEF already created a new render process
        },
      ));

      // ④ Create the underlying CEF browser
      await _controller!.initialize(url: "https://www.example.com");

      setState(() => _ready = true);
    });
  }

  @override
  void dispose() {
    _controller?.dispose();       // close individual webview
    WebviewManager().quit();      // shutdown CEF (app exit)
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        body: _ready
            ? _controller!.webviewWidget
            : const Center(child: Text("Initializing...")),
      ),
    );
  }
}
```

### 时序规则

整个生命周期的关键顺序是：

```
① WebviewManager().initialize()   —— 启动 CEF 引擎（整个 App 调用一次）
          │
② WebviewManager().createWebView()   —— 创建 WebViewController
          │
③ controller.setWebviewListener(...) —— 注册事件监听（必须在 ④ 之前）
          │
④ await controller.initialize(url:)   —— 创建底层浏览器，返回 textureId
          │
⑤ controller.webviewWidget            —— 放入 widget 树中渲染
          │
⑥ controller.dispose() + manager.quit() —— 退出时逐个销毁
```

> **为什么 ③ 必须在 ④ 之前？**
> 页面事件（`onPageStarted`、`onPageFinished` 等）从 `initialize()` 触发的首次导航
> 就开始产生。如果在 `initialize()` 之后注册监听，首次导航的事件将丢失。

### ValueNotifier 用法

`WebViewController` 继承 `ValueNotifier<bool>`，当 CEF 浏览器就绪后 `value` 变为 `true`。
可以直接作为 `Listenable` 用于 `ValueListenableBuilder`，替代手动管理 `_ready` 标志：

```dart
ValueListenableBuilder(
  valueListenable: _controller!,
  builder: (context, value, child) {
    return value
        ? _controller!.webviewWidget
        : _controller!.loadingWidget;
  },
)
```

> 完整示例（含地址栏、Cookie 管理、JS 桥、DevTools、进度条）见
> [`example/lib/main.dart`](https://github.com/hlwhl/webview_cef/blob/main/example/lib/main.dart)。

## 5. 常用功能速览

以下是最常用的功能代码片段。完整的 API 参考见 [Dart 层 API](2-Dart层API.md)。

### 5.1 导航

```dart
controller.loadUrl("https://www.example.com");     // 加载 URL
controller.reload();                                 // 刷新
controller.goBack();                                 // 后退
controller.goForward();                              // 前进
bool canBack = await controller.canGoBack();         // 是否有后退历史
String? title = await controller.getTitle();         // 获取页面标题
controller.stopLoading();                            // 中止加载
controller.openDevTools();                           // 打开开发者工具
```

### 5.2 页面事件

| 事件回调 | 触发时机 | 典型用途 |
|---------|---------|---------|
| `onPageStarted` | 页面开始加载 | 显示 loading 动画 |
| `onPageFinished` | 页面加载完成 | 注入 JS SDK、更新标题 |
| `onNavigateRequest` | 导航发生前 | 拦截跳转（返回 `NavigationPolicy.cancel`） |
| `onProgressUpdated` | 加载进度更新 | 进度条（0.0 – 1.0） |
| `onPageFailed` | 加载失败 | 显示错误页面、重试 |
| `onConsoleMessage` | 页面 console 输出 | 调试日志收集 |
| `onRenderProcessTerminated` | 渲染进程崩溃/OOM | 自动 `reload()` 恢复 |

所有回调均为可选，通过 `WebViewEventsListener` 传入。`onPageFailed` 携带 `WebViewError`
对象（含 `code`、`message`、`extraInfo["url"]`）。

### 5.3 JavaScript 桥

**Dart → JS**：

```dart
controller.executeJavaScript("console.log('hello from Dart')");   // 无返回值
var result = await controller.evaluateJavascript("1 + 1");        // 返回 Future<dynamic>
```

**JS → Dart**（需要先注册通道）：

```dart
// Dart side: register channel
await controller.setJavaScriptChannels({
  JavascriptChannel(
    name: 'Print',
    onMessageReceived: (JavascriptMessage message) {
      debugPrint(message.message);   // payload from JS
      // Reply to JS callback
      controller.sendJavaScriptChannelCallBack(
        false,                        // error = false
        "{'code':'200'}",
        message.callbackId,
        message.frameId,
      );
    },
  ),
});
```

```javascript
// JS side: send message to Dart
$cef.Print.postMessage(JSON.stringify({msg: 'hello'}));

// JS side: send message with callback
$cef.Print.postMessage(JSON.stringify({msg: 'hello'}), function(err, res) {
  console.log('reply:', res);
});
```

**通道名规则**：必须匹配 `^[a-zA-Z_][a-zA-Z0-9.]*$`（否则端口注册时触发断言错误）。
JS 侧 `$cef.<通道名>` 在页面加载时由 V8 扩展自动注入，无需手动声明。

> JSBridge 的完整调用链（V8 扩展 → CefJSBridge → 跨进程消息 → Dart）见
> [JSBridge 详解](4-JSBridge详解.md)。

### 5.4 Cookie

```dart
// Set
WebviewManager().setCookie("example.com", "token", "abc123");

// Delete
WebviewManager().deleteCookie("example.com", "token");

// Visit all
Map<String, Map<String, String>> all = await WebviewManager().visitAllCookies();

// Visit specific domain (isHttpOnly = true to include http-only cookies)
var cookies = await WebviewManager().visitUrlCookies("example.com", true);
```

> Cookie API 属于 `WebviewManager`（全局），不绑定到具体的 `WebViewController`。
> `visitAllCookies()` 返回格式为 `{domain: {key: value, ...}}`。

### 5.5 用户脚本注入

```dart
var scripts = InjectUserScripts()
  ..add(UserScript(
    "console.log('injected at load start')",
    ScriptInjectTime.LOAD_START,
  ))
  ..add(UserScript(
    "console.log('injected at load end')",
    ScriptInjectTime.LOAD_END,
  ));

var controller = WebviewManager().createWebView(
  injectUserScripts: scripts,
);
```

`LOAD_START` 脚本在 `onPageStarted` 前注入；`LOAD_END` 脚本在 `onPageFinished` 前注入。
脚本在每个页面的浏览器创建时通过 `executeJavaScript` 执行，注入 `<style>` 等 DOM 操作亦有效。

### 5.6 开发者工具

```dart
controller.openDevTools();
```

调用后 CEF 将打开独立的 Chrome DevTools 窗口，可用于调试 HTML/CSS/JS、网络请求、性能。

## 6. 配置项总览

### 初始化参数

`WebviewManager().initialize()` 接受三个可选参数：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `userAgent` | `String?` | `null`（使用 CEF 默认） | 自定义 User-Agent 字符串 |
| `processMode` | `ProcessMode` | `ProcessMode.processPerSite` | CEF 进程模型 |
| `cachePath` | `String?` | `null`（各平台自动推导） | CEF 缓存根目录 |

### ProcessMode 选择

| 模式 | 进程数 | 适用场景 | 风险 |
|------|--------|---------|------|
| `processPerSite`（默认） | 约 5–8 个 | **生产环境**，加载任意网页 | 低 |
| `processPerTab` | 更多 | 需要最大进程隔离 | 内存占用高 |
| `singleProcess` | 1 个 | 调试、Kiosk、受信内容 | **渲染进程崩溃 → App 退出**，无沙箱 |

> **生产环境推荐 `processPerSite`**。`singleProcess` 仅适合调试或嵌入式/Kiosk 场景
> 加载受信内容，不应加载不受信的第三方网页。

### cachePath 默认路径

不显式指定 `cachePath` 时，各平台自动推导唯一路径，避免多实例缓存文件锁冲突：

| 平台 | 默认路径 | 唯一性来源 |
|------|---------|-----------|
| macOS | `~/Library/Caches/<bundle_id>/cef` | Bundle Identifier |
| Windows | `%LOCALAPPDATA%\<exe名称>\cef` | 可执行文件名 |
| Linux / eLinux | `$XDG_CACHE_HOME/<exe名称>/cef` | `/proc/self/exe` 文件名 |

> **多实例场景**：如果同一框架的不同项目同时运行，不指定 `cachePath` 时路径自然不同。
> 只在特殊情况下（如缓存复用、位置定制）才需要显式指定。

### 编译期 GPU 渲染选项

| 选项 | 平台 | 说明 |
|------|------|------|
| `WEBVIEW_CEF_GPU_TEXTURE` | Windows / Linux | 默认 `ON`；关闭则回退软件像素缓冲 |
| `WEBVIEW_CEF_GPUTexture` | macOS | podspec 恒定为 `1`（仅 GPU 路径） |
| （无） | eLinux | 仅软件渲染 |

GPU 纹理关闭后，CEF 通过 CPU 像素缓冲渲染到 Flutter Texture，性能较低但兼容性更好。
遇到 GPU 渲染异常（黑屏、花屏）时可在 Windows / Linux 上尝试关闭此选项。

详见[构建与集成](7-构建与集成.md)和[渲染管线](5-渲染管线.md)。

## 7. 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 首次构建 / `pod install` 很慢 | CEF 约 330 MB 下载 + `libcef_dll_wrapper` 编译 | 正常现象；可用 `~/.cef/tar/` 离线加速（见[第 2 节](#2-添加依赖)） |
| macOS 链接失败，提示 deployment target 12.0 | Runner target 部署目标低于 12.0 | Podfile 加 `platform :osx, '12.0'`，Xcode 中 Runner 的 Deployment Target 也设为 ≥ 12.0 |
| macOS 只有一个进程，无子进程 | 未添加 helper 嵌入钩子 | 按 [3.1 节](#31-macos) 在 Podfile `post_install` 中添加 `WebviewCEF.install_helper_phase` |
| Windows 键盘输入无效 | 消息循环中缺少 `handleWndProcForCEF` | 按 [3.2 节](#32-windows) 在消息循环末尾添加该调用 |
| Linux 粘贴（Ctrl+V）不可用 | 未安装 `xclip` | `sudo apt install xclip` |
| eLinux 键盘无法输入 | eLinux 无原生键盘支持，由 Dart 侧处理 | 无需原生侧改动；正常现象 |
| 渲染进程崩溃导致整个 App 退出 | 使用了 `singleProcess` 模式 | 切换为 `processPerSite`；也可监听 `onRenderProcessTerminated` 自动 `reload()` |
| 两个 CEF App 同时运行，浏览器创建失败 | 缓存目录文件锁冲突 | 为不同 App 指定不同的 `initialize(cachePath:)` |
| 修改 `common/` C++ 源码后行为不生效 | macOS: helper 未重编；其他: 未 clean build | macOS 需重新 `pod install`；详见[构建与集成](7-构建与集成.md)「重新编译」 |
| 需要 arm64 + x86_64 双架构 macOS 包 | 默认仅构建本机架构 | 详见 [macOS Universal 构建](8-macOS%20Universal构建.md) |
| GPU 渲染异常（黑屏、花屏） | GPU 驱动 / 兼容性问题 | Windows/Linux 关闭 `WEBVIEW_CEF_GPU_TEXTURE` 回退软件渲染 |
| 调试时要用单进程简化排查 | 默认多进程 | 开发调试时 `initialize(processMode: ProcessMode.singleProcess)`；正式上线切回 `processPerSite` |
| `onPageStarted` 等事件首次导航收不到 | 监听器注册晚于 `controller.initialize()` | 确保 `setWebviewListener()` 在 `await controller.initialize()` 之前调用 |
